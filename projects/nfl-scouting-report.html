01 / PROJECT OVERVIEW

A scouting tool designed around football decisions.

The problem

Raw play-by-play data contains valuable information about offensive identity, defensive performance, and how teams respond to game situations. But transforming those plays into an opposing-team scouting profile requires cleaning data, defining situations, aggregating metrics, and presenting the results in a readable format.

The approach

I built an R Shiny application that lets a user choose an NFL team, season, offensive or defensive perspective, and situation. The app connects team efficiency, pass tendencies, weekly trends, fourth-down behavior, and player contributions in one workflow.

It also provides a separate offense-versus-defense comparison and a downloadable HTML scouting report, so the analysis can move beyond the dashboard into a shareable document.

02 / DATA & SCOUTING PIPELINE

From individual plays to scouting insights.

The application builds its analysis datasets separately, then reads processed files at startup. That keeps the interactive experience focused on evaluating teams rather than downloading and preparing play-by-play data during each session.

  1. 01

    Load

    Use nflreadr::load_pbp() to pull 2023–2025 play-by-play data from nflverse.

  2. 02

    Define context

    Clean team abbreviations, keep qualifying run/pass plays, and create down, distance, field-zone, score, and time indicators.

  3. 03

    Calculate

    Compute EPA, success, explosive-play rates, context-adjusted pass tendency, a separate fourth-down dataset, and player summaries.

  4. 04

    Communicate

    Load processed .rds objects into Shiny, filter interactively, visualize findings, and render a matchup report with Quarto.

03 / APPLICATION WALKTHROUGH

The scouting workflow in action.

These screenshots come directly from the application's GitHub repository. The views connect broad team identity to more specific situations, matchups, fourth-down choices, and player contributors.

FEATURE 01

Build an offense or defense profile

The Overview page puts team identity and efficiency measures into context using the selected season, unit, and situation.

  • Compare passing tendency, EPA per play, and pass rate over expected (PROE).
  • Benchmark selected team measures against same-season league baselines.
  • Switch between offensive and defensive perspectives without changing the overall workflow.

FEATURE 02

Compare an offense with an opposing defense

Matchup Mode places one team's season-long offensive profile beside another team's defensive profile, highlighting differences in efficiency and tendency.

  • Compare pass rate, EPA per play, success rate, explosive-play rate, and PROE.
  • Investigate down-by-down differences and rolling EPA patterns.
  • Use the selected situation filter to narrow the matchup lens. These are profile comparisons, not predictions of a final score.

FEATURE 03

Study real fourth-down decision distributions

Fourth-down behavior needs a different denominator from ordinary offensive play analysis. The app builds a separate dataset that retains punts and field-goal attempts as well as run/pass decisions.

  • Show fourth-down play count and average yards to gain.
  • Calculate the share of qualifying fourth-down plays on which a team attempted a run or pass.
  • Break out go-for-it tendencies by yards-to-go category.

FEATURE 04

Bring individual players into the scouting picture

The Player Layer aggregates play-by-play outcomes for passers, rushers, and receivers, then presents compact tables with player headshots.

  • Passers: qualifying plays, EPA per play, and explosive rate.
  • Rushers: carries, yards per carry, and EPA per play.
  • Receivers: targets, EPA per target, and explosive rate.

04 / ANALYTICAL METHODS

The definitions matter as much as the charts.

Rather than showing a single team ranking, the app applies explicit rules for play success, game context, passing tendency, and fourth-down decisions.

PLAY EFFICIENCY

EPA, success rate, and explosives

The team profiles summarize nflverse expected points added (EPA) and a down-aware success rule. A play is successful if it gains at least 40% of the required yards on first down, 60% on second down, or 100% on third/fourth. Explosive plays are runs of at least 10 yards or passes of at least 20.

success = case_when(
  down == 1 & yards_gained >= 0.40 * ydstogo ~ TRUE,
  down == 2 & yards_gained >= 0.60 * ydstogo ~ TRUE,
  down %in% c(3, 4) & yards_gained >= ydstogo ~ TRUE,
  TRUE ~ FALSE
)

PASS TENDENCY MODEL

Pass rate over expected (PROE)

A binomial logistic regression estimates pass probability given down, yards to go, field position, score differential, quarter, and time remaining in the half. The difference between actual passing behavior and modeled expectation provides a contextual tendency measure.

pass_model <- glm(
  is_pass ~ down + ydstogo + yardline_100 +
    score_diff + qtr + half_seconds_remaining,
  data = model_data, family = binomial()
)
proe_play = is_pass - expected_pass_prob

FOURTH-DOWN ANALYSIS

Accounting for the decisions not to go

The standard run/pass dataset cannot estimate a useful go-for-it rate by itself: it excludes punts and field-goal attempts. The fourth-down pipeline therefore retains all four relevant play types and labels run/pass attempts as going for it.

filter(
  down == 4,
  play_type %in% c("run", "pass",
                   "punt", "field_goal")
)
went_for_it = if_else(
  play_type %in% c("run", "pass"), 1, 0
)

How to interpret the models: PROE is calculated from a model fitted to the included historical plays and scored on those plays. It is a descriptive tendency measure in this application, not a validated prospective play-call forecast. Likewise, the matchup differences are season-profile comparisons rather than game-outcome probabilities.

05 / ENGINEERING & PROBLEM SOLVING

Turning analysis into a usable product.

01

Build once, filter many ways

Challenge: Loading and recomputing multi-season play-by-play data for every interaction would make exploration cumbersome.

Implementation: A preprocessing script saves scouting, pass-model, fourth-down, and player-summary objects that Shiny loads from disk. Reactive filters then support the selected team, season, unit, and situation.

02

Separate fourth-down decisions

Challenge: Filtering only run and pass plays makes every fourth-down entry look like a go-for-it attempt.

Implementation: The data pipeline explicitly creates a separate fourth-down table that also includes punts and field goals, enabling more meaningful decision-rate calculations.

03

Produce a report outside the app

Challenge: A scout or analyst may need to share a matchup summary without asking someone else to reproduce the interactive selections.

Implementation: A Shiny download handler passes offense, defense, season, situation, and project directory to a parameterized Quarto report, rendered as HTML in a temporary location.

06 / SCOPE & NEXT STEPS

A scouting starting point, not a game simulator.

What the project demonstrates

An end-to-end R analytics workflow that converts multi-season NFL play-by-play data into interpretable team and player views, context-aware passing metrics, fourth-down behavior summaries, and a shareable scouting report.

It demonstrates the combination of football knowledge, data preparation, statistical modeling, dashboard development, and clear communication required to make analytics usable.

Important limitations

  • Data period: The documented build covers 2023–2025, not a continuously updated current-week feed.
  • Modeled tendency: The pass model is assessed in-sample; its out-of-sample calibration and forecast accuracy are not established here.
  • Small samples: Specific down/distance or late-game situations may contain relatively few qualifying plays.
  • Matchup interpretation: Profile gaps are descriptive differences, not causal advantages or predicted game scores.
  • Fourth downs: Go-for-it rate measures observed run/pass decisions among included fourth-down play types, not whether going for it was optimal.

If I were extending this project

Next priorities would be an automated season-refresh pipeline, model validation on held-out seasons, small-sample uncertainty displays, injury and personnel context, and a fourth-down expected-value framework that evaluates the consequences of each decision rather than only its frequency.
