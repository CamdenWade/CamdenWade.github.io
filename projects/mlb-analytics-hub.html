01 / PROJECT OVERVIEW

One place to explore the numbers behind the game.

The problem

Baseball evaluation often means moving among player leaderboards, team summaries, batted-ball data, and static reports. Those sources can answer related questions, but the workflow is fragmented when someone wants to move from a broad comparison to a specific player.

The approach

I developed MLB Analytics HUB as a multi-view R Shiny application that brings selected FanGraphs statistics, a limited Baseball Savant Statcast sample, exploratory analysis, and shareable scouting profiles into a consistent interface.

The emphasis is on making analysis navigable: start with a leaderboard, narrow the context, compare players, inspect percentiles, and produce a player-focused HTML report.

02 / METHOD & DATA PIPELINE

From raw data to usable analysis.

The project separates data preparation from the running Shiny app so the interface can load locally processed datasets instead of repeatedly requesting external data on each page load.

  1. 01

    Acquire

    Retrieve 2025 FanGraphs hitter/pitcher leaderboards with baseballr, plus a short Baseball Savant Statcast sample.

  2. 02

    Standardize

    Clean source column names, normalize player/team fields, retain selected Statcast variables, and save processed .rds files.

  3. 03

    Analyze

    Compute relative player percentiles, team summaries, contact-quality measures, comparisons, and exploratory WAR-model outputs.

  4. 04

    Deliver

    Use Shiny reactive inputs and reusable functions to power dashboards; render selected player reports with Quarto.

03 / PRODUCT WALKTHROUGH

Explore the application.

These are real screenshots from the GitHub repository. Each view is designed around a practical baseball question rather than a collection of charts without context.

FEATURE 01

Find and filter player performance

Separate hitter and pitcher leaderboards surface traditional and advanced statistics in sortable, team-filtered tables.

  • Compare hitters using WAR, wRC+, OPS and counting statistics.
  • Evaluate pitchers with WAR, ERA, FIP, WHIP and rate metrics.
  • Use player headshots when source identifiers are available.

FEATURE 02

Evaluate pitchers with their own metrics

A dedicated pitcher view avoids treating pitching evaluation as the same problem as hitting evaluation.

  • Surface ERA and FIP alongside strikeout and walk rates.
  • Keep team context visible while sorting and reviewing qualified pitchers.

FEATURE 03

Turn statistics into player profiles

Player pages pair headline metrics with percentile visuals to give raw values a clearer comparison point.

  • Use different metric sets for hitters and pitchers.
  • Reverse the percentile direction for metrics where lower is better, such as ERA and FIP.
  • Apply team-color styling to improve visual identification.

FEATURE 04

Compare players side by side

The comparison tool makes it easier to investigate the differences between two hitters or two pitchers without switching pages.

  • Select two players and view key metrics together.
  • Pair a comparison table with a visual metric breakdown.

FEATURE 05

Move from players to team context

Team views bring together selected hitters and pitchers and display WAR-based leaders to make roster-level exploration more convenient.

  • View included-player summaries for hitting and pitching.
  • Inspect the top performers within a selected team.
  • See team-colored visualizations for faster scanning.

FEATURE 06

Make exploratory modeling visible

The Modeling Insights tab exposes a hitter WAR regression through coefficient summaries, fit statistics, and rows with large fitted-versus-actual differences.

  • Inspect model coefficients and summary diagnostics.
  • Review players with larger in-sample model residuals.
  • Treat the results as exploratory associations, not causal findings.

04 / ANALYTICAL DEPTH

Methods behind the interface.

The app combines descriptive baseball analysis with a deliberately simple regression model and a small contact-quality exploration.

PLAYER EVALUATION

Metric-aware percentile rankings

For a selected player, the app measures the share of players in the included dataset with values at or below that player's mark. For lower-is-better pitching metrics, it reverses the direction so that higher displayed percentiles consistently represent stronger results.

pct <- mean(vals <= player_value) * 100
if (!higher_is_better) pct <- 100 - pct

REGRESSION

Exploring offensive metrics and WAR

A linear model estimates hitter WAR using HR, RBI, SB, AVG, OBP, SLG, OPS, and wRC+. The interface shows R-squared, adjusted R-squared, in-sample RMSE, coefficients, and the largest fitted-value differences.

lm(war ~ hr + rbi + sb + avg + obp +
     slg + ops + w_rc_plus, data = model_data)

CONTACT QUALITY

Statcast sample analysis

The Statcast view summarizes exit velocity, launch angle, hard-hit rate, and an explicitly labeled barrel-like proxy. That proxy is based on a simple velocity/angle rule, not MLB's official barrel classification.

launch_speed >= 98 &
launch_angle >= 26 &
launch_angle <= 30

05 / ENGINEERING & PROBLEM SOLVING

The decisions behind the build.

01

Different sources, different schemas

Challenge: FanGraphs and Baseball Savant provide different field names and structures.

Implementation: A dedicated build script cleans column names, standardizes identifiers, and writes smaller processed R datasets for the app.

02

Many views, one interface

Challenge: Leaderboards, profiles, comparisons, and modeling require different data shapes and outputs.

Implementation: Analysis and plotting functions are separated into focused R files, while Shiny reactivity handles user selections.

03

Turning a dashboard into a deliverable

Challenge: An interactive view is useful in the moment, but a scouting workflow also needs a shareable summary.

Implementation: A parameterized Quarto document generates a player-specific HTML report from the same processed datasets.

06 / SCOPE & NEXT STEPS

What this project demonstrates—and where it can improve.

What I built

A publicly linked R Shiny application connecting baseball data preparation, several analytical views, relative player evaluation, exploratory modeling, and an automated scouting-report workflow.

It demonstrates an ability to move from a sports question to reproducible analysis, interactive presentation, and a tangible report—not just produce a standalone chart.

Important limitations

  • Season scope: Leaderboards are drawn from the 2025 season with source qualification filters, not every MLB player-season.
  • Statcast scope: The current sample covers April 1–3, 2024; it is not a full-season batted-ball dataset.
  • Team summaries: They summarize the included players and should not be mistaken for official full-roster team statistics.
  • WAR model: Coefficient interpretation is limited by correlated features and the absence of a documented holdout evaluation.

If I were extending the project

My next priorities would be adding multi-season data, broadening Statcast coverage, introducing an out-of-sample modeling benchmark, and writing automated checks around the data pipeline and report generation.
